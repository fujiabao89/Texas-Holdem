# TEX-56 真实多人移动设备验收

本目录提供真人实机验收步骤，配合已有真实链路自动化，不生成自动通过结论。要求以 [05 §16](../../../docs/05-frontend-spec.md#16-验收标准前端侧)、[06 §9～§12](../../../docs/06-testing-strategy.md#9-ui-e2e-与人工验收) 和 [TEX-56](https://linear.app/texas-holdem/issue/TEX-56) 为准。本轮状态、环境、矩阵和证据索引填入 [验收记录](../../../docs/03-engineering/TEX-56-acceptance.md)。

## 开始前

1. 固定测试环境的 Web SHA、game-server SHA、lockfile SHA-256、部署配置版本和隔离测试数据库标识。部署者确认实际运行版本；`/health` 为 200 不证明运行了候选版本。确认测试域名、数据库隔离和诊断采集权限后才开始建房。
2. 按 06 §9.1 准备中低档 Android/Chrome、iPhone 15/Safari 和 Windows/Edge；填写准确型号、OS/浏览器版本、RAM、实际 CSS 视口、方向、缩放、网络类型。浏览器自动升级后补跑受影响项目。替换设备需记录与最低性能档的差异并由用户决定是否接受，不能默认满足矩阵。
3. 准备至少三名真人 A/B/C 参加第一轮，第四名真人 D 只在第二轮加入。测试昵称只用 A/B/C/D 等临时别名；六/十人桌可增加独立浏览器身份，但必须记录哪些是操作者、哪些是辅助身份，不能把辅助身份算作真人。
4. 关闭通知预览，截图/录像隐藏私密牌面、浏览器地址中的邀请码和个人信息。禁止导出 HAR、认证帧、原始 WS payload、sessionStorage、完整控制台或未筛选服务器日志。只使用既有诊断白名单；脱敏后再上传受控证据位置。手牌隔离通过本机只读检查和受控自动化交叉验证，不能把原始底牌数据写进报告。
5. 在同一候选运行真实链路和完整时序 RC 门禁。已有本地配置时按 [real](../real/README.md) 和 [timeline](../real/timeline/README.md) 运行；缺环境必须记录“未执行”。两套 real 配置串行运行，不能把 `TEX_E2E_BASE_URL` 指向公网就声称测了目标部署：现有配置会启动本地服务和隔离 schema。

```powershell
pnpm install --frozen-lockfile
pnpm exec playwright install chromium firefox webkit
# TEX_TEST_DATABASE_URL 由受控测试环境注入，不把连接串写入命令记录或截图。
pnpm test:e2e:real
pnpm test:e2e:timeline:rc
pnpm exec tsx tests/e2e/real/timeline/audit.ts
```

也可使用已有 `timeline.yml`，输入完整候选 SHA。该工作流提供隔离 PostgreSQL 和 Linux/Xvfb；结果仍只代表自动化环境，不代表目标手机、公网部署、容量/Soak 或发布批准。

## 两轮完整旅程

| 步骤 | 操作与检查 | 留证 |
| --- | --- | --- |
| M01 创建与加入 | A 建房，B/C 在各自真实设备通过邀请码加入，选座并 Ready；核对全部客户端成员、座位和开局阻塞原因 | 同时段各设备 Lobby 截图、设备代号 |
| M02 第一轮开局 | A 开赛，记录 Room R 和 Tournament T1；核对公共牌、Actor、Stack、D/SB/BB 一致，本人底牌仅本人可读 | T1 标识、公开状态摘要；不记录私密牌面 |
| M03 合法行动 | 在每台手机上经真实业务到达 Fold/Check/Call/Bet/Raise/All-in 和 Time Bank 可用分支；逐项操作快捷金额、Slider、±、精确输入、两步 All-in | 分支与 handId、提交前后公开金额；未命中分支填未执行 |
| M04 单视口 | 软键盘收起时公共牌、本人手牌、Actor、全部当前合法动作同时可达；精确输入时检查键盘打开、确认和收起后的可达性；检查 Safari Safe Area 与浏览器工具栏展开/收起 | 竖/横屏、实际视口、是否滚动/遮挡；不可用记缺陷 |
| M05 网络与后台 | 各手机分别在本人行动期及结算期进行短暂断网、Wi-Fi↔蜂窝切换、后台至少 20 秒后返回；其他人继续合法操作 | 时间段、断网方式、前后 handId/Seat/Stack/盲注，恢复不重播旧动画 |
| M06 摊牌与分池 | 合法行动命中普通摊牌、全下、主/边池；核对公开手牌、最佳五张和各池分配可理解，比较结束前不突出赢家，结算无遮挡 | 只保留已公开且获允许的牌面，优先遮盖全部牌面；未命中分池不能填通过 |
| M07 第一轮完赛 | 完成 T1，各客户端冠军/排名/最终筹码一致；在原有会话中刷新赛果，并用同一浏览器会话直接导航结果 URL；另以无凭证会话验证安全降级 | 各客户端结果、刷新和直接访问结果；不复制凭证到新会话 |
| M08 返回筹备 | A 从结果页点击“返回大厅，筹备下一局”；仍为 Room R，尚未自动开赛；邀请码恢复，旧 Ready 清空 | 同房间标识、各成员 Ready、邀请状态 |
| M09 新人加入 | D（未参加 T1）用恢复的邀请码加入；分别验证未入座/未 Ready/保留成员离线会阻塞开局，解决阻塞后全员重新 Ready | 新人代号、阻塞提示与解除后的截图 |
| M10 第二轮 | 从 Lobby 显式开赛；T2 ≠ T1、Room 仍为 R、初始筹码和配置正确；D 实际参赛并完成 T2 | T1/T2、配置、初始与最终公开筹码 |
| M11 多轮隔离 | T2 中及完赛后访问 T1 结果和历史，显示 T1 的权威内容；旧赛果不能隐式重开，邀请码比赛中暂停 | 两场标识、导航结果与隔离检查 |

每个步骤都要记录每台设备结果。一次通过不能覆盖另一手机；需要重测时保留首次失败及关联修复候选，重新运行受影响场景。不要为赶完赛使用 DB 改筹码、伪造帧或修改客户端 store。

## 座位和性能补充

- 在 2/3/6/10 人桌分别核对相对 seatIndex 顺序、稀疏座位、Heads-up 的 D/SB 关系、跨手 D/SB/BB 轮转；每种人数在刷新及重连后再核对。额外建桌不替代上述同 Room 两轮旅程。
- Windows Edge 检查 1366×768 与 1920×1080、键盘下注/焦点、音效；Android 与 Safari 检查触控、首次用户手势解锁音频、系统 Reduced Motion 和恢复后音效。
- 中低档 Android 在 10 人桌与 Showdown 采集真实触控响应、帧间隔、长任务、动画降级和可用内存指标。阈值见 06 §10.1；记录工具/版本、采样区间、样本数、p95 计算口径和观察开销。平均 FPS 不能冒充 p95；若工具无法采集某项填“未测”，不能用桌面 CPU 模拟补位。
- 内存至少记录空闲大厅、第一场后、重开后和第二场后的同口径值，注明单位、采样方式与 GC 不确定性；这类短程测量不替代正式 Soak。

## 结果回填与缺陷

每项记录 `PASS / FAIL / NOT_RUN`、设备代号、Room/Tournament/handId、开始结束时间（含时区）、预期与实际、证据链接和复现步骤。辅助身份与模拟网络必须显式标注。没有证据、样本不足或场景未到达时填 NOT_RUN。

发现产品问题先检索 Linear 是否已有同一缺陷，复用唯一任务并标记严重级别；本任务不跨模块修复。P0/P1 或必测未执行阻断发布；P2 保留唯一任务、影响和用户处置决定。确认测试房间已关闭、临时本地服务/schema 已清理；不得清理其他运行或共享环境数据。把验收记录、同候选自动化报告和受控媒体索引关联 TEX-30/TEX-43 后，由 Codex 给出建议，用户作最终发布决定。
